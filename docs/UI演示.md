# UI 演示

启动：`npm run dev`。构建：`npm run build`。检查：`npm run lint`、`npm test`。

打开首页后，点击「进入演示后台」。登录页已填入示例信息，任何非空输入都只进入演示，不会校验或发送密码。演示登录标记保存在当前标签页的 sessionStorage 中；退出会清除标记。这不是实际身份认证。

## 可以体验

- 激活码：按状态筛选、搜索、生成 1–20 个示例码、复制。演示限制不是正式业务规则。新增数据在页面导航时保留，刷新后重置。
- 教师：搜索、按激活状态筛选、跳转对应教师的 API 用量。
- 课程、评估、字典：选择或拖入文件，也可使用示例材料；体验模拟传输、处理中、成功或结构化错误反馈。
- API 用量：按教师、服务类型筛选，展示不同计量单位和空状态。
- 小屏设备：通过顶部菜单打开导航，宽表格可横向滚动。

## 接口接入边界

分两类，别混：

**真实接口**（走 `src/api/client.ts`，打的是 Spring Boot 后端）

- `官方素材`（`/files`）：上传 / 列表 / 标记删除，对应 `/admin/files`。
- `AI 试评`（`/ai-score`）：故事评分与单题评分，对应 `/api/ai/score`、`/api/ai/score-answer`、
  `/api/ai/tasks/{task_id}`、`/api/ai/rubrics`。

**示例数据**（`src/demo/data.ts`，不代表服务端契约）

激活码、教师账号、课程 / 评估 / 字典材料、API 用量。它们的上传流程仍是本地定时器模拟，
不产生真实请求。

## AI 试评怎么用

1. 先用 `官方素材` 上传几张图片（也可在试评页直接选本机图片——浏览器里转 base64）。
2. 打开 `AI 试评`：
   - **故事评分（18 项）**：填故事依据与儿童原话，给每个图片分组选规则（选项来自
     `/api/ai/rubrics`，即服务端评分标准），提交后轮询任务，展开看 6 宏观 + 5 微观 + 叙事产生性
     + 每个分组的分数、理由与原文证据。
   - **单题评分（1 项）**：填题号 / 题目 / 提示与作答时机（提示前 / 提示后），图片同样可选本机或已上传素材。
3. 图片两种来源都符合契约：本机选图走 `INLINE_IMAGE`，已上传素材走 `SERVER_FETCH`（只给编号，服务端按编号取图）。

注意事项：

- **任务失败不是 HTTP 错误**：接口返回 200，`data.stage` 是 `FAILED`，失败原因在 `data.failure.code`，
  页面对每种失败码都给了下一步建议。
- 任务只在服务端内存里，**不写入任何业务数据**；服务端重启或结果过期（默认 30 分钟）就查不到了。
- 每次提交都用新的 `request_id` / `input_revision`；「失败后重试」沿用同一对标识并把 `retry_attempt` 加一，
  这也是契约的要求。
- 评分标准版本留空即用服务端当前版本，任务凭据会回实际版本。
